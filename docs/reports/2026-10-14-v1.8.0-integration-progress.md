## Token 指标判断

### 发现并修正的问题

1. **跨轮速度混入旧样本**：本机 task_started/token_count 只读采样确认，`total_token_usage.output_tokens` 是会话累计输出，不会随新一轮归零。上游靠数值回落分段不足以识别换轮，而且数值回落时没有清掉已收集的旧区间。现有速度用例换成不同轮次速度后，原代码实际返回 40，期望 20，先失败再修复通过。
2. **轮次身份**：后端在受限尾部窗口内识别 task_started，将 turn_id 附加到用量事件；前端按 turn_id 切段，兼容没有轮次标记的旧记录和累计值回落。新轮只有一条事件时显示占位，不拿旧轮速度充数。
3. **异步旧读数**：请求完成后重新核对当前会话、节点、开关与页面可见性，丢弃切换会话后的迟到结果。
4. **DOM 生命周期**：状态栏不跨轮缓存 DOM 节点和子节点，重建时重新获取；分组观察器以弱归属记录代替长期菜单节点引用。
5. **读取边界**：文件尾部读取固定为本次窗口大小，避免 rollout 正在追加时 read_to_end 突破预期边界。继续使用 512 KiB 起始窗口、8 MiB 上限、最多 24 条事件，不退回整读历史。

本次更新了现有速度、存储和路径用例中的断言/夹具，没有另建测试集。临时只读探针和浏览器夹具只在 target/temp 留作验收证据。

### 正常工作范围

- 速度：最近三个有效区间的输出 Token 增量/时间平均，按轮次切段；少于两个事件、过短/过长间隔显示 `--`。
- 缓存命中率：最近一次调用的 `cached_input_tokens / input_tokens`。
- 上下文占用：最近一次调用的 `total_tokens / model_context_window`；缺少有效窗口显示 `--`。
- 两分钟无新事件后淡化速度，保留缓存和上下文读数。

速度是**用量事件间的生成吞吐**，包含工具等待/调用间隔，不是逐 Token 解码计时。长推理或长工具调用期间读数可能暂不刷新；不能用它精确比较供应商解码速度。
