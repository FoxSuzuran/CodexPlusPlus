# Codex++ 1.10 更新与个人版整合

日期：2026-10-18。个人版基线 `e2b7deb9`，上游发布 `v1.10.0`（源码 `85f9117f`，北京时间 2026-10-17 23:53 发布）。

## Fast 的选择

采用上游原生 Fast 链路，删除个人版旧 Fast 菜单、徽标、输入监听和发送前速度设置同步。保留自定义模型速度元数据转发、Plan 模式同步、pure API / OpenAI 的提交模型修正。

| 比较项 | 原个人版 | 1.10 原生链路 |
| --- | --- | --- |
| 交互 | 原生与扩展两套入口，需要同步选择、设置和发送状态 | 原生菜单与请求使用同一套状态 |
| 日常额外工作 | 自定义菜单、输入事件、会话读取及设置等待 | 不再维护上述扩展速度控制链 |
| 启动 | 无原生大模块改写 | 开启解锁时准备原生模块，显式启动后重载一次 |
| Fast / Ultrafast | 扩展层判断与写入 | 原生解析实际 tier；仍受模型元数据及权限限制 |
| 供应商推理速度 | 无本地证据 | 无本地证据，不能由菜单或 tier 字段推断 |

结论：日常交互优先使用原生实现，减少重复状态与监听；并非所有阶段都更快。对已有 14,403,691 字节原生源码的隔离检查，四个门控各唯一匹配，完整模块解析改写约 2.2–2.5 秒。这是单次本地诊断样本，不是应用启动计时、长会话切换收益或供应商推理速度对照。

解锁默认关闭，只在用户开启“原生 Fast 强制解锁”并完整重启后生效。不将旧 `codexAppServiceTierControls` 或旧全局速度偏好自动迁移成新的解锁授权。升级后在原生菜单确认所需速度档位；API 供应商是否支持和如何计费仍取决于实际服务。

## 原生 Ultrafast 与兼容修复

- 直接执行原生函数 fixture，验证显式请求、默认模型、默认队列、显式队列的 `ultrafast` 透传；验证 `ultrafast_mode:false` 拒绝，以及独立速度权限下 Fast 禁止但 Ultrafast 仍可用。
- 上游移除旧控制器时也删除了自定义 descriptor 的 `additionalSpeedTiers` / `serviceTiers` 转发。Rust 仍发布这两项元数据，原生菜单又依赖它们；缺少原生目录项的模型因此可能丢失 Ultrafast。只保留两数组转发及 descriptor 应用，不恢复旧控制器，也不给未知模型补造档位。
- 保留 Standard、未知供应商 tier、camelCase / snake_case 参数、原始返回值、请求选项与错误；官方账号、Copilot、远端执行和 durable 会话继续遵守各自原生路径。
- 保留 Plan 的设置完成等待、快速改选、失败阻断、空回合确认，以及 Daybreak 模型漂移修复中的条件更新和原生鉴权。

## 其他更新与保留

接入 1.10 的外部 Agent 协作（显式开启）、Anthropic messages 协议、命名 API Key、本地配置供应商、管理器会话索引缓存与分页、Skills 列表和仓库处理、配置及协议安全修复、Dream Skin 1.5.20。

个人版继续保留：

- 去广告及不等待网络健康探测的管理器启动；设置草稿保护、分页请求过期响应处理、菜单与弹窗可访问性。
- 皮肤隐藏暂停、文本流忽略、祖先去重、顶部渐隐层原生 `:has(*)`，以及当前会话识别跳过明确非活跃侧栏行。
- 图片预览右上角避让、首页欢迎文字与输入框居中对齐。
- 扩展路由白名单；只新增只读的页面列表，不开放 `/cdp/evaluate` 表达式执行。
- 原 `target`、固定 Windows 发布配置、单应用 EXE、仅 `rlib` 管理器入口、本地 AGENTS.md。

合并同时修正状态栏冲突：持久状态只存数据，不缓存 DOM；每次重新获取节点，不再把节点缓存缺失误判为每次都切换会话；连续失败退避 30 秒，保留栏位及已有读数，有效空响应恢复预热。

管理器会话索引与分页不等同于官方聊天页面的历史渲染；不能据此声称截图中的全部原生转圈已消失。
