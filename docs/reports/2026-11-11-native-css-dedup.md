# 2026-11-11 原生聊天切换与重复 CSS

## 结论

继续独立排查，没有启动子代理。确认原生异步 CSS 分片重复携带大量全局规则，
会放大聊天切换、菜单及其他 DOM 更新的样式计算开销。已加入可恢复的样式去重，
保留彩虹、Dream 主题及原生样式。本次修复减轻了一个已验证的原因，**没有彻底解决聊天切换卡顿**。

前半轮已检查上游 Issue/PR；本次修改不涉及依赖升级、后台调度或聊天数据。
此前彩虹动画及性能采集器的修复继续保留，见
[全局排查报告](2026-11-11-global-lag-investigation.md)。

## 证据与边界

原生点击 trace 中仍有两次数百毫秒、涉及数千元素的样式重算。
原生侧栏位置计算、选择工具及滚动容器的几何读取会同步结算这些样式；
它们是阻塞发生的入口，不能直接认定为最早的失效来源。
在关闭应用 JS 的静态 DOM/CSS 副本中也能复现整树计算开销。

一份原生样式样本有 23,349 条规则，其中 6,360 条文本重复；最终保守去重删除
5,816–5,939 条叶子规则。隔离样本中，同一 DOM 变更由 1,481ms 降至 826ms。
最终现场单次去重约 111–148ms，后续聊天切换不会重新遍历 CSS。

以下真实鼠标切换使用相同两个已缓存聊天，在 Rust 编译和相关测试结束后采样。
采样前恢复完整主题结构标记，保持 ayacyann、原有主题 CSS 及彩虹动画：

| 顺序 | 条件 | 聊天一切换 ms | 聊天二切换 ms | 对应样式计算 ms |
| --- | --- | ---: | ---: | --- |
| 1 | 去重 | 2325 | 2449 | 1583 / 1508 |
| 2 | 原件 | 3782 | 3241 | 2539 / 2398 |
| 3 | 去重 | 1928 | 2269 | 1337 / 1569 |

这组六次样本的切换均值减少约 36%，样式计算均值减少约 39%。
其他对照组也出现原件回退后仅 2.17–2.28 秒的情况；缓存与并发界面更新有明显波动，
不能承诺固定百分比或将全部延迟归因于重复 CSS。修复条件仍有约两秒切换延迟。

以下候选没有作为产品改动保留：

- 固定 Radix focus guards、改动 portal 容器、推迟选择工具调用：无稳定收益。
- 停用主题、高亮规则、原生关系/结构选择器：不能完整解释剩余停顿，且不能以删样式交付。
- 配色相对颜色表达式、缓存已解析颜色：收益不足。
- 侧栏 `content-visibility:auto`：隔离样本有收益，现场反向对照不足以证明稳定改善。
- Chromium 143、148、157 的静态对照均复现相关成本，没有证据支持仅靠换内核解决。

重型逐选择器失效追踪会显著放大停顿，未将其绝对耗时用于最终收益统计。

## 实现与样式保留

新增 `11-native-style-cache.js`，在启动时调用；分片清单及组装产物同步更新。
仅处理 `app://-/assets/` 下原生 CSS。按样式表和规则的逆序，保留最后一份完全相同的
规则；比较包括分组条件、命名层和完整声明。匿名层、嵌套样式子树及其他不支持的分组保留。
不改选择器、颜色、动画或声明值。

仅在原生样式表集合、顺序或启用状态变化时，先按原位置恢复，再重新去重。
监听 head 的 link 变化及 load；每两秒只比较样式表身份与状态，兜底检测
不产生 DOM 事件的 `CSSStyleSheet.disabled`。不观察聊天正文，也不随流式 token 扫描规则。
热重载会先撤销旧实例，避免叠加观察器和计时器。

限制：假定原生静态资源不在加载后被其他代码直接编辑 CSSOM；若宿主增加这种行为，
需扩展恢复协议。程序直接切换 `sheet.disabled` 的检测最多有两秒延迟。

最终在同一个 JS 任务中比较去重前后的 5,246 个已布局元素、17 项计算样式，
共 89,182 项无差异；避免将流式文字或动画时间推进误判为样式变化。
确认彩虹动画运行、主题 CSS 与排查前逐字节一致、结构标记刷新正常。
诊断热重载曾漏恢复主题结构标记，已恢复；该过程没有修改仓库主题源码或用户设置。
