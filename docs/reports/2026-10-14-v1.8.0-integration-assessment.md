## 必须解决的兼容交集

### 模型身份、能力与旧会话

采用最终源码的严格解析规则：非 `cpx-` 请求交给默认成员，模型名原样转发；未知 `cpx-` 模型硬报错，不静默切换供应商。发布说明同时保留了中间版本“按模型名归属成员”的描述，但该策略已被后续严格解析取代，迁移以标签源码为准。

升级后旧会话、自动压缩、子代理可能继续提交历史裸模型名或旧前缀。必须确认默认成员与用户预期一致，失效前缀需重新选择模型；不能按同名模型猜测供应商，也不修改历史会话内容来掩盖路由失败。

分组身份使用上游的 `codex_plus_group`、`codex_plus_group_id`、`codex_plus_default` 和目录级 `codex_plus_default_group_id`；这些是新功能需要的展示身份，不能被自用“私有控制字段过滤”误删。原有 Fast 私有控制字段继续不泄漏到原生目录。

保留模型能力的自用优先级、原生运行时能力、新模型仅声明 Fast 时不伪造推理能力，以及 Standard/Fast/Ultrafast/继承队列。Plan/Daybreak 的发送前同步和失败阻断保持；模型换名不能导致旧参数发送或关闭原生权限检查。

### Windows 多开与退出

本地使用 `CODEX_PLUS_APP_STATE_DIR`，1.8.0 使用 `CODEX_PLUS_STATE_DIR`，并在 worker options 中新增 `state_dir`，显式构造 settings/status/launch options。预演自动保留了两个环境变量写入，不能直接交付该重复实现。

统一内部调用为上游常量和显式 state_dir；移除内部旧变量写入，worker 状态路径继续验证绝对路径和实例归属。旧 options 的缺字段兼容要核对，现有实例迁移通过完整重启后重建启动参数完成，不删除实例和会话数据。

保留自用 Windows PID/EXE/worker 参数/options 路径身份校验；上游仍没有等价 Windows 身份检查。同时采用上游停止 worker 时不带 `taskkill /T` 的行为，并核对 Codex 服务与 worker 的实际退出归属，避免误杀子进程树或遗留旧服务。

额度监督任务、服务、CDP、托盘、自动接管和 native-browser 恢复沿同一生命周期退出，重启先取消并等待旧任务，再复用端口。

### 状态栏、皮肤与扫描

新状态栏保留，不能拿它替代每日统计：前者显示当前会话速度/缓存/上下文，后者记录跨会话每日用量和费用。它使用独立 `/thread-usage-live`，从 rollout 文件尾部取事件；保留 512 KiB 起始窗口、8 MiB 名义上限、后台线程读取和扩展白名单边界，不改成逐秒整读历史。

源码中的状态栏缓存 node/parts，分组缓存 activeList。结合本地“DOM 重建重新获取”的约定，接入时校验当前节点归属并在重建后重新获取，避免沿用旧节点引用。状态栏异步读数返回时还应核对当前会话，避免切换会话后暂时写入上一会话的数据。

上游分组扫描定时器在菜单关闭时仍每 600ms 执行入口检查，虽然不会继续解析列表；状态栏活跃期约 1.2 秒轮询。源码有重复注入 dispose、数据指纹和隐藏页处理，但这些不能直接证明本机无卡顿。重点核对一个运行实例、一个扫描调度器、监听器释放、弹层/输入区/图片层与 DreamSkin 的共同边界，不另建第二套调度系统。
