## 1. Bennett 在没有 Markdown 预览时仍反复读取原生前端资源

位置：已安装的独立市场脚本 `C:\Users\29035\AppData\Roaming\Codex++\user_scripts\market-bennett-ui-improvements.js`，`scanEditors` 第 2271 行、`loadNativeKatex` 第 1122 行、`discoverKatexUrl` 第 1105 行。脚本 SHA-256 为 `d18781e5faeb44c962a0398ecbebb91e9a9e1a01a824e71d6667114e79c978b0`。

**触发与影响：** 全页子节点变化触发公式增强的扫描，即使右侧没有 Markdown 预览编辑器，仍然调用 `loadNativeKatex()`。找不到 KaTeX 时，发现过程读取主 renderer 文件的全部文本并执行匹配，随后清空失败的 Promise；下一次扫描再次执行相同工作。它会在正常流式更新中持续占用主线程，也反复记录警告。资源可能由本地协议或缓存提供，不能把这些读取次数直接换算成外网流量或磁盘读取次数。

**证据：**

- 现场状态为 `previewEditors: 0`、`nativeKatexLoaded: false`，错误为 `Codex native KaTeX chunk was not found`。
- 可见窗口的 CPU 样本记录到 `discoverKatexUrl` 累计约 242 ms，其中自身约 234 ms。
- 提取实际函数，设定零编辑器与相同的发现失败，分批运行 20 次扫描：读取资源 20 次、警告 20 次、安装编辑器增强 0 次。

**最小修复：** 清理失效编辑器后，发现编辑器为空就返回；实际需要公式时再加载。对同一原生 bundle 的发现失败使用有期限的缓存或退避，并保留版本变化、到期及显式重试后的恢复能力。不要永久关闭公式功能。

**验收：** 无预览时连续 DOM 更新不触发资源读取；有预览且可加载时公式正常；同 bundle 失败不会逐批重读，新 bundle 或重试后能够恢复。市场脚本独立于 EXE，修复交付需要单独的脚本补丁。

## 2. 全局 Array.filter 补丁为普通业务数组增加两次遍历

位置：`assets/inject/renderer-inject/60-plugin-marketplace.js:33`，关联 `50-navigation.js:168` 与 `60-plugin-marketplace.js:8`。

**触发与影响：** 补丁改写全局 `Array.prototype.filter`。只要过滤后长度减少，即使回调与插件市场无关，也先遍历原数组查找官方 marketplace 字段，再判断回调源码是否匹配。普通列表过滤被增加两轮字段探测，列表越长、过滤越频繁，额外工作越多。

**证据：** 2 万条普通对象，每次筛选一半，正常返回 1 万条，但补丁额外访问 `marketplaceName` / `name` 合计 4 万次。现场可见窗口中的补丁调用栈累计约 401 ms；该累计包含原始过滤工作，不能全部算作补丁开销。

在 VM 中仅调整检查顺序，先使用已有 WeakMap 源码缓存与正则，再保留匹配路径原有的数据检查：普通过滤结果不变，额外字段访问从 4 万次降为 0。本轮三种回调用例的结果在调整前后相同。

20 次过滤、7 组取中位数的普通对象微基准：原始过滤约 8.5 ms，现有补丁约 349.2 ms；顺序调整后的独立组为原始约 11.0 ms、候选约 11.5 ms。Node VM、运行环境和数据形态影响绝对耗时，以访问次数与输出一致性为主要证据，不推算真实应用倍数。

**最小修复：** 前移缓存后的回调结构检查，不匹配则直接保留原始过滤结果。保留官方目录数据校验、现有兼容行为和诊断，不移除整个插件兼容补丁。

**验收：** 非插件过滤不遍历额外字段；官方目录、featured、无关回调以及匹配相似但应拒绝的回调继续覆盖；组装注入产物并执行现有兼容测试。

## 3. Dream Skin 在窗口隐藏后仍做结构扫描

位置：`assets/inject/upstream/dream-skin/windows/renderer-inject.js:1039` 的调度器、第 1062 行的结构观察器、第 1158 行的保底定时器。该文件是实际使用的外部皮肤产物，不能与旧的未启用分支混为一谈。

**触发与影响：** 窗口隐藏时仍有后台流式输出或结构变化，调度器继续执行 `ensure`，刷新结构部件与 predicates；没有可见性暂停与恢复合并。30 秒保底检查也继续运行。

**证据：** 提取实际调度器，设定 `document.hidden = true`，分开触发 100 批变化，仍执行 100 次 `ensure`。隐藏窗口现场 profile 中，`ensure` 累计约 311 ms，其内部 `refreshPredicates` 约 229 ms；两者包含关系明确，不相加。

**最小修复：** 隐藏时只合并待处理标记，恢复可见时刷新一次最新状态；保底扫描也遵循可见性条件，并清理新增监听。通过 `scripts/sync-dream-skin.mjs` 的本地适配维护，避免直接修改上游 vendor 后下次同步丢失。

**验收：** 后台 100 批变化不重复全扫，恢复前台完成一次更新；主题、路由和结构重建保持及时，销毁无残留。实现时同时核对另一平台产物。

## 4. 用量状态栏把明确失败当成等待数据，退避分支失效

位置：`assets/inject/renderer-inject/83-usage-statusline.js:339`，关联第 369、392 行。

**触发与影响：** 桥接请求返回 `{ status: "failed" }` 而非抛异常时，`refresh` 先把失败次数归零，再返回空值。现有失败计数仅在异常分支增加，因此无缓存的会话一直按“等待第一条用量”的频率请求，无法进入已有的隐藏和 30 秒退避逻辑。

**证据：** 对实际 `refresh` / `tick` 连续返回 10 次明确失败：请求 10 次、失败计数仍为 0、下一次间隔 2500 ms、隐藏次数 0。

**最小修复：** 区分业务失败、有效空结果与成功数据，只有成功响应重置计数；明确失败使用已有计数和退避。保留新会话尚无 token 事件时的正常等待行为。

**验收：** 连续失败能够退避，恢复后重新显示；有效空事件不误判为故障；切换会话与已有缓存场景继续覆盖。

## 5. MCP 导入的迟到预览可为另一份 JSON 解锁确认

位置：`apps/codex-plus-manager/src/ManagementPages.tsx:177`，实际导入入口见 `App.tsx:3795`。

**触发与影响：** 对 A 点击预览，等待期间将输入改成 B；输入变化虽然清空预览，迟到的 A 响应仍会写回并启用确认。界面展示 A，确认按钮实际传入当前 B，用户可能导入没有核对过的配置。

**证据：** 隔离 Edge 中显示“将导入：preview-A”，导入回调收到的却是 `unpreviewed-B` 的 JSON。

**最小修复：** 将预览结果绑定到请求序号和输入快照；只接受仍对应当前输入的响应，确认时再次核对快照。沿用现有解析和后端校验。

**验收：** A 慢、B 修改、B 重新预览、A 迟到等顺序均不能使过期结果生效；失败后不会保留可确认的旧预览。

## 6. Skills 仓库保存失败仍关闭抽屉，导致输入丢失

位置：`apps/codex-plus-manager/src/ManagementExtra.tsx:20` 的 `saveRepo`。失败结果来源见 `src-tauri/src/commands.rs:5445`，校验见 `crates/codex-plus-core/src/skills.rs:638`。

**证据：** 隔离 Edge 输入 `invalid/owner`，命令返回 owner/name 字符校验失败；抽屉关闭，重新打开 owner 为空。这个场景是已完成但失败的 Promise，不是网络异常。

**最小修复：** 仅成功后关闭抽屉；失败保留草稿和现有错误提示，允许直接修正重试。

**验收：** 校验失败与落盘失败都保留输入，成功后才关闭；重复保存和取消行为不变。

### 两处共享开销修复

1. **当前会话识别反复解析无关侧栏行。** `currentSessionRef()` 原先先完整解析每行的会话和 React 主机信息，再检查当前行。现有 `isCurrentSessionRow()` 对 `data-app-action-sidebar-thread-active="false"` 本就必定返回 false；现在在共享入口提前跳过。Fast、滚动与其他调用者一并受益，没有新增缓存。当前行的 ID / 主机冲突校验、缺属性的旧版本路径和路由回退保持不变。
2. **顶部渐隐层的空子节点判断触发全页扫描与属性写入。** Dream Skin 唯一的 `:has(*)` 消费者为 `[data-app-shell-main-content-top-fade]:not(:has(*))`，但缓存算法给全页非叶节点都写 `data-dream-has-11`。本地同步适配器仅让这条稀少且已锚定的判断保留原生 CSS，其他 16 项继续缓存，编号不重排。双平台构建时校验唯一出现位置，上游变更会明确失败。删除相应全页扫描分支；不改 canonical CSS、子模块和模块层级。皮肤修订号更新为 `29-thread-navigation`。
