## 已修复的耗时与竞争

### 请求日志并发和裁剪

检查并吸纳上游草稿 PR [#3093](https://github.com/BigPizzaV3/CodexPlusPlus/pull/3093) 的适用补丁，原提交为 `0d75dd676f63205405794748f396a716fbdbd2be`；它尚未在上游合并，本地经过本轮验证使用。

同进程的追加、裁剪与清空现在串行化，每条记录连同换行一次编码。读取器与用量补证器只在复制文件字节期间持锁，反序列化在锁外进行，避免把原位裁剪的中间状态当作完整日志。裁剪只读取约 1 MiB 尾部，保留原文件及其访问控制；写入失败保留诊断，同时继续原有用量汇总。

这把锁不协调其他进程。原位裁剪遇到磁盘写入错误仍可能留下不完整文件，补丁不恢复已经损坏的历史记录。

### 只解析需要的记录

此前完整日志读取、分页读取和实时尾部读取都会遍历并反序列化所读范围内的每条记录，再保留最后 `limit` 条。现在从尾部解析，凑够结果就停止；分页额外确认一条匹配记录，以保持 `more`，并单独读取首条有效记录以保持 `oldestMs`。

无筛选的 2,500 条测试样本、300 条分页请求，由反序列化 2,500 条变为约 302 条。这里是解析工作量的变化，没有测量并宣称同等比例的总耗时下降。稀疏筛选或没有匹配时仍可能扫描完整日志，完整分页也仍会复制整份有界文件。

回归覆盖零条限制、精确边界、没有匹配、时间和供应商筛选、两端损坏行及空行。实时请求流仍只读取 256 KiB 尾部，不足时保留完整读取回退。

### 数据库与异步调度

`local_session_titles` 继续使用每批最多 200 个 id 的批量查询，改成只读连接，避免查询期间数据库消失时意外创建空文件。标题属于展示补充，忙锁等待设为 50 毫秒；忙时沿用短 id，继续查询其他数据库，全部标题找到后提前结束。没有添加新索引、连接池或改变数据库格式。

管理器的 `load_request_logs`、`load_request_flow`、`load_gateway_usage` 和清空日志命令改为异步命令，把同步文件读取、SQLite 查询和锁等待放到现有阻塞线程池。命令名、参数、返回结构、费用估算和标题回退保持原有行为。

协同 `wait_task` 每 200 毫秒查状态的节奏不变，复用执行器已有 `on_store`，将 SQLite 查询移出 Tokio 工作线程。忙锁测试占用数据库独占锁，同时在单线程运行时等待定时器，确认其他异步工作仍能获得调度。没有添加通知协议或改变跨进程排队、取消及终态语义。

### 界面刷新

请求日志自动刷新不再与未完成的读取重叠。筛选变化、手动刷新及清空后的刷新仍可立即发起新读取，旧响应及旧错误不能覆盖新结果；卸载后不接受迟响应。恢复可见时立即尝试刷新，用户关闭自动刷新时不新增后台读取。

今日用量统计在窗口隐藏时停止读取，恢复可见立即读取，同一 hook 中合并未完成的请求。失败保留上次统计，卸载清理监听与定时器。没有删除筛选、诊断信息或其他界面功能。

复用测试 harness 执行 `aa946bbf` 与本轮源码的真实回调：一个日志读取未完成时连续触发 20 次定时器，调用数由 21 次降为 1 次；窗口隐藏期间连续触发 20 次用量刷新，新增读取由 20 次降为 0 次。这里模拟慢响应与可见性，不访问真实数据库，也不代表整个程序的耗时比例。证据为 `target/temp/runtime-self-check-20261116/polling-comparison.json`。

## 剩余边界

这一轮没有验证新 EXE 的冷启动、真实管理器操作耗时与同条件聊天切换；外部每日 token 用量扩展的全页几何扫描仍待单独验证。某些低频状态读取，以及运行中请求时钟的背景渲染，仍有继续检查的空间，本轮没有统一改写所有轮询。

50 毫秒内无法获得数据库读取机会时，日志页可能短暂显示会话短 id，后续刷新可恢复标题。请求日志并发锁仅覆盖同进程；没有通过削减安全校验、停止日志记录或丢弃任务来提高响应速度。

实现依据：[Tauri 异步命令](https://v2.tauri.app/develop/calling-rust/#async-commands)、[Tokio 阻塞操作](https://docs.rs/tokio/latest/tokio/task/fn.spawn_blocking.html)。本轮改动沿用现有线程池和依赖。
