## 压缩诊断边界

当前内置 CLI 为 `0.163.0-alpha.11.2`，本次没有升级或替换官方 CLI。

对应 tag 的 `codex-rs/core/src/session/async_compaction.rs:43-49` 要求同时启用异步压缩、关闭 TokenBudget，并且 provider 能力为 V2。`codex-rs/model-provider-info/src/capabilities.rs:20-27` 将 V2 定义为通过 Responses 端点发送 `compaction_trigger`。

这不是普通 `/responses/compact` 是否能调用的同义词。显式声明能力只改变客户端选择，不能证明供应商能正确返回 V2 压缩结果，也不能解释 Krill 之前失败的完整原因。尤其不能把所有失败一概归为供应商不支持。

该 CLI tag 的 `take_ready` 仍在原 receiver 上调用 `try_recv().ok()?`，失败时不会清除 receiver；后续 `wait_for_pending` 可能再次 await 已消费的 receiver。OpenAI PR #55581 于 2026-10-20 合并，修复此类后台压缩失败后的 panic，但新实现不在当前内置 CLI 中。

- https://github.com/openai/codex/blob/rust-v0.163.0-alpha.11.2/codex-rs/core/src/session/async_compaction.rs
- https://github.com/openai/codex/blob/rust-v0.163.0-alpha.11.2/codex-rs/model-provider-info/src/capabilities.rs
- https://github.com/openai/codex/pull/55581

没有发送真实供应商请求或主动触发计费压缩。因此交付结论是“升级构建与本地配置修复已验证”，不是“供应商异步压缩端到端已恢复”。
