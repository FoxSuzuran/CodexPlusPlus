## 构建中发现并修复的兼容交集

1. 两个 Claude PowerShell 资源原为 UTF-16LE，而仓库 `*.ps1 text eol=crlf` 会在 Windows 检出时破坏字节对齐；现场 Parser 已报语法错误。本次改为 UTF-8 BOM，保留构建脚本原逻辑。上游开放 PR #2522 已确认同一原因，本次参考其编码修法，没有合入它的 Store/MSIX 检测、副本目录替换等其它改造。
2. Windows inject-cn.ps1 原先没有把新增的语音/汉化开关交给 hook，补传两个布尔值，避免显式关闭失效；默认值与正式版一致。
3. 新 hook 原先固定从主用户目录读听写凭据，本次沿用既有 `CODEX_PLUS_STATE_DIR` 的非空绝对路径规则，确保状态目录覆盖后的读写位置一致；相对路径仍回退默认目录。

三项回归在修复前分别失败，修复后通过。PowerShell 用 Parser 只做语法解析，没有运行准备/启动副本脚本。未声称 Windows Claude Store/MSIX 完整链路已修复；该部分仍受上游正式版的现有平台边界约束。

参考：<https://github.com/BigPizzaV3/CodexPlusPlus/pull/2522>。
