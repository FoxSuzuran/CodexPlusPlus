# 体验与构建持续优化（2026-11-06）

以个人 `main` 的 `dcea6090` 为起点，沿用上一轮运行和构建优化。没有停止当前 Codex++、刷新当前聊天页面或覆盖安装目录的 EXE。本次先定位问题，再分轮修改、复验和构建。

## 第一轮：日志轮转不再反复阻塞请求

检查了上游当前 Issue 和 PR。#2935 报告了 Windows 日志超过 24 MiB 后轮转失败、桥接积压的同一机制；未找到已合入的对应修复。#2916 的用户脚本控制协议涉及较大范围的生命周期变更，未直接吸纳。

`LogSink::write_line` 原先在周期检查时仅 flush，仍持有追加句柄就调用原子替换。失败会在更新下一次检查时间前返回，使之后每条日志都重新执行轮转。

统一初次打开、路径切换和周期轮转的链路：先关闭旧句柄；无论轮转是否成功都重新打开并推进检查时间；保存本次记录后再返回轮转错误。保留原有追加写、文件大小限制及错误上报。

6 项日志单元测试通过，包含打开文件上的真实轮转、失败退避和失败时继续保存记录。没有修改真实日志，也没有声称复现了正式进程的完整阻塞现场。多个独立进程同时轮转仍可能发生竞争，失败后按现有 5 秒周期重试。

## 第三轮：构建缓存和资源体积

安装并使用 cargo-sweep 0.8.0，工具位于 `target/tools/cargo-sweep`，安装缓存仍使用仓库 `target`。旧工具链清理预览没有找到可回收项。

`scripts/build-windows.ps1` 先编译当前 workspace 的 dev/test 图，再按固定顺序完整构建 Vite 和执行 `cargo xrelease`。Cargo JSON 消息用于核对两份成功构建的产物，并保留对应指纹；取得 dev/release 的 Cargo 文件锁后，调用 cargo-sweep 清理本次构建前的历史指纹。未知二进制指纹保守保留，构建或核验失败时不执行清理。预览、删除明细、产物清单及编译输出记录在 `target/temp/windows-build`。

清理仅作用于仓库的 Cargo 产物，不作用于安装目录、发布目录、Sherpa 静态库、诊断记录或 E 盘归档。cargo-sweep 本身不管理 incremental 目录，本轮保留这些缓存，避免以删除当前增量缓存换取表面空间收益。

另外将八份皮肤 JS/CSS 接入已有 zstd 无损打包和 LazyLock 按需解压缓存，保持源文件及调用接口。没有增加依赖或切换发布 profile。Rust 逐字节验证还原内容，前端契约测试同步读取构建资源清单。
