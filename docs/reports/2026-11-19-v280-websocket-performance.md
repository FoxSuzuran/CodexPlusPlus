# Codex++ v2.8.0 续接与界面性能

合入北京时间 2026 年 11 月 19 日发布的 v2.8.0（`f6fa88b2`），保留个人 fork 的布局、增强开关、模型配置和单应用构建。上游 `c209314f` 修复了闲置断线、换模型和路由变化后的 WS 恢复信号，对应 Issue #3169、#3176、#3183。v2.8.0 也合入了按模型使用上下文窗口和压缩阈值的修复 `c0fba34a`。当时上游 `main` 随后的两个提交只更新了赞助内容。

## WebSocket 与上下文

- WS 在新装和缺少 `responsesWebsocket` 字段的配置中默认开启。显式关闭继续生效。ChatGPT 官方账号和 OpenAI API 走原生 WS，第三方中转或混合协议池在握手时返回 426，由 Codex 通过 HTTP/SSE 发送上下文。当前机器的活动网关走第三方 Responses 中转，会使用这条兼容路径。
- 收到 `previous_response_id` 时，代理检查原上游连接、模型和 Key。无法续接，或准备完成后、发出增量前连接关闭时，返回 `previous_response_not_found`，由 Codex 重发完整输入。生成已经提交后出现断线，代理报告中断，避免再次执行一轮。升级成功仅证明支持 WS 帧；它不能证明中转会保留前文和推理项。
- Codex 重发本回合需要的完整输入，其中可以包括客户端已有的压缩窗口。跨供应商切换继续用现有策略处理各家签发的加密压缩内容。#3175 描述 DeepSeek 需要把推理内容随工具结果传回；使用 SSE 可规避中转接受 WS 却不保留续接状态的情况。
- #3171 的上游排查记录显示，HTTP 压缩后发的是摘要和新增消息，工具输出会再次占用窗口。第三方回到 SSE 后走原有的压缩探测和摘要兜底。若仍频繁压缩，可用请求日志里的压缩前后输入量和实际生效的模型窗口判断原因。
- 本机 `codex-cli 0.169.0-alpha.11.1` 在回环测试中先执行工具，再收到续接失效错误。重连后的请求带了原始消息和工具结果，并完成回合。另一组在握手收到 426 后用 HTTP/SSE 发送完整输入并完成回合。网关端到端回归覆盖两条本地入口的 426 和 SSE 回退，并核对上游收到的消息、工具结果、鉴权和请求日志。

## 卡顿对照

用 CDP 采集运行中桌面的 CPU 和时间线。22 秒被动观察出现 2 个长任务，最长 152 毫秒。补充采样定位到插件市场的全局 `Array.filter` 兼容补丁。以合并后的 v2.8.0 代码为基线，在实际 Edge 浏览器对相同输入做了对照。

| 路径 | 结果 |
| --- | --- |
| 插件过滤 | 对同一普通回调过滤 400 次，兼容正则检查从 1,200 次降到 3 次。官方插件例外和原生过滤结果保持。 |
| 会话切换 | 保留 20 个后台输入框，三条模拟输出更新期间点击切换 8 次，模型工具栏几何读取从 168 次降到 8 次。编辑和速度切换保留。 |
| 扫描调度 | 清掉已无对应入口的快速编辑器菜单探测。浏览器回归验证流式子节点更新不触发全量扫描，结构变化仍会补挂控件。 |
| 原生 WS 流 | 普通增量帧在无需响应中间件时直接转发。生成请求提交后释放大 JSON 对象，只保留亲和所需字段。命名流并行和同流 FIFO 通过回归。 |
| 微信连接页 | 慢状态读取期间 12 次额外轮询不再产生新请求。手工读取或保存完成后，早先的状态不会盖回新设置。 |

这组浏览器数据衡量具体操作次数。排查记录和原始采样位于 `target/temp/v280-ws-performance`。新版实际安装后的日常会话切换耗时仍待测量。

## 回归

Rust 核心单元、集成和网关端到端测试共通过 4,761 项，另有 47 项按原配置忽略。工作盘上的测试目录没有独立的 8.3 别名，该 Windows 短路径用例单独排除。前端通过 2,484 项，原有 2 项跳过，TypeScript 检查通过。浏览器另测了 54 种快捷控件布局和 162 次速度档位切换。

Windows 单应用 EXE 的隔离启动验证了 WS 新配置默认开启、显式关闭和重新开启，以及“未知供应商”筛选。管理器隐藏到托盘的 11.5 秒采样内发出 0 次后台网关轮询。EXE 的嵌入资源与生产构建逐字节核对，标准清理移除了 5.03 GiB 的历史 Cargo 产物。
