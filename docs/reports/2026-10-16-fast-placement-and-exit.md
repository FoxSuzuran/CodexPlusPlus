## 退出等待

新增两个隔离回归均在原实现失败：

- CDP HTTP 端点收到请求后持续不响应，守护线程处理 tick 的分支期间不会再读取停止信号，1 秒停止预算超时。
- 会话已经执行自己的清理，但另一个 `spawn_blocking` 工作仍未返回，直接销毁 Tokio runtime 会继续等待，退出回执在 1 秒内无法返回。测试最终释放阻塞工作，不留下挂起线程。

守护线程将停止信号覆盖到整个探测阶段；已经开始的注入仍等待其脚本注册清理完成。会话继续等待启动事务、helper、原生浏览器恢复和状态清理，然后停止 runtime，不再等待无关的附属阻塞任务。退出终态在等待工作线程前释放全局锁，后续启动能及时得到“正在退出”，不会重新建立 runtime。

管理器退出中的 supervisor 停止也移入已有后台任务。新增 `app.shutdown_started`、`launcher.cleanup_phase`、`launcher.cleanup_complete`、`app.shutdown_complete` 及耗时，便于区分后续个案卡在 helper、浏览器恢复还是宿主退出。

## 历史对话滚动

只读检查确认本机的 `.thread-scroll-container` 使用普通 column 布局，已保存的多个位置在原内容高度的底部。上游 #129 和 #2274 的位置保留与存储异常保护已经在本地历史中；本轮检索没有找到可直接吸纳的高度变化专项修复。

原逻辑只按保存时的绝对 scrollTop 恢复。重新打开历史后，消息、图片或窗口变化会改变内容高度；恢复锁仍使用旧数值，并拦截原生滚到底部。在真实 Edge 布局的隔离场景中，内容从 1000 增至 2400 像素，原实现停在离底部 1400 像素处，且底部请求被拦截。此回归修复前失败、修复后通过，不宣称已经在用户实际历史页面完成复现。

快照增加可选的 `atBottom`；原来在底部时按当前内容的底部恢复，旧快照根据保存时的 scrollHeight/clientHeight 兼容识别。主动上翻仍恢复原阅读位置，用户滚动会取消自动恢复。零尺寸、尚在加载的容器不覆盖有效快照，旧的空快照也不执行恢复。没有新增轮询、全页观察器或强制锁底。

`scripts/test-thread-scroll-browser.cjs` 覆盖普通与 column-reverse 两种真实滚动布局，验证内容增长、旧快照、阅读位置、用户取消和空容器。`scripts/test-fast-placement-browser.cjs` 保留速度按钮的独立布局回归。
