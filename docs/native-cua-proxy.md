# 官方 CUA 代理继承

Windows 官方浏览器和 Computer Use 共用 `cua_repl`。桌面 AUMID 激活不会继承
Codex++ 的启动环境，官方也会重新生成 MCP 配置。本适配在官方
CUA 的 MCP 启动环境中追加 `NODE_OPTIONS=--import=…`，载入代理初始化模块，
使原生工具宿主继承代理。已有的 `NODE_OPTIONS` 保留；不限制 Node、工具入口或
worker 所在目录，也不要求固定的运行时布局、入口脚本结构或服务列表。

只随增强功能启用，不影响其他 MCP、独立 Node REPL 或终端。权限预加载、认证、
trusted services、启动参数及原始错误处理保持不变；不依赖旧浏览器身份补丁。
WindowsApps 内置运行时和用户缓存运行时使用同一方式，无需写入应用安装目录。

## 代理选择

优先使用工具进程已有的代理，其次使用启动 Codex++ 时的代理，最后使用现有
系统静态代理检测。兼容大小写；只有 HTTP/ALL 代理时为 HTTPS 补齐同一来源的值。
保留工具和调用方的 `NO_PROXY`，补上 `localhost,127.0.0.1,::1`。
所有来源都没有代理时，初始化模块不改变工具环境。

启动时探测选定代理端口，失败向工具 stderr 写不含地址和凭据的提示，继续保留
该代理，不自动回退直连。不设置 `NODE_USE_ENV_PROXY`，不修改系统代理或开启 TUN。
首版不把 PAC 的单 URL 决策转换成全局代理。

## 生命周期与恢复

资源由 launcher 会话持有。先取得独占文件锁、恢复上次遗留修改，再准备当前插件
选定的插件启动配置。正常退出、启动失败、管理器停止会话均等待恢复完成。
运行期间每两秒检查插件选择、系统代理和增强开关；代理变化在下次工具启动时生效。
官方重新生成插件配置后会重新附加预加载。关闭增强会移除预加载，不终止已运行的工具进程。

控制文件和恢复记录位于应用状态目录的 `native-cua-proxy`。
恢复记录在更新配置前落盘，仅记录本次改动的 `NODE_OPTIONS`。恢复时保留配置的
其他字段；用户同时修改 Node 参数时只移除自己的预加载。停用时清空控制文件中的代理值。
旧版本留下的入口脚本补丁仍按原恢复记录清理，避免升级后叠加两种接入方式。

仅更新官方 unified-computer-use 插件 `.mcp.json` 中的 CUA 启动环境，不修改
运行时文件、ASAR 或原生二进制，不固定运行时版本或代理端口。
读取或写入失败会记录 `native_cua_proxy.prepare_failed` / `refresh_failed`。

## 验证

`cargo test -p codex-plus-core --lib native_cua_proxy` 覆盖来源优先级、大小写、
回环绕过、无代理、代理不可达、重复安装、版本选择、缓存外运行时、配置重新生成、
异常恢复、保留用户改动、旧补丁恢复，以及真实 Node 子进程的权限预加载、环境继承和退出码。
`cargo test -p codex-plus-core --test all launcher::` 覆盖启动和失败清理顺序。

另有显式忽略的 `manual_official_runtime_proxy_monitor` 实机诊断用例。它会临时
修改本机官方插件的启动环境；只有手动选择该用例才运行，按 Enter 后等待恢复。
常规测试均用隔离目录。

独立官方 CUA 实例通过不代表正常桌面冷启动完成验收。交付报告应分别记录启动路径、
浏览器读取时间、桌面操作和恢复结果，保留仍待验证的项目。
